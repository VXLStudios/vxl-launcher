## Launcher Changelog v0.2.5

### New Features

#### Privacy & streaming
- **Streamer mode** - Toggle in Settings → Behaviour. Hides the play-screen nametag, blurs account names in the account switcher (reveal on hover), and hides server addresses on the servers panel while keeping servers usable.

#### VXL Studios & API
- **Studios catalogs via Launcher API** - Modrinth and CurseForge VXL Studios browse data is loaded from cached catalogs on `api.voxelstudios.co.uk` instead of calling Modrinth/CurseForge directly from the webview.
- **Rust API proxy** - `fetch_vxl_api_json` avoids browser CORS when the UI needs JSON from the Voxel API.
- **Updater & changelog URLs** - Release and changelog requests use the `/v1/launcher/...` paths on the Voxel API.

#### Library & discovery UI
- **Profile groups on library cards** - Group name appears as an inline badge after version/loader on library profile cards.
- **Modrinth / CurseForge source tabs** - Active source uses a green highlight on Modrinth (matching the existing orange CurseForge style) so the selected marketplace is obvious at a glance.

#### Settings
- **Configurable log level** - Choose error through trace in Settings → Behaviour. `VXL_LOG_LEVEL` overrides the saved setting when set in the environment.

#### Profiles & data (backend)
- **SQLite profile store** - Profiles and mods persist in `app.db` in the launcher root folder (not under `meta/`). Existing `profiles.json` is migrated once; the old file is renamed to `profiles.json.migrated`.
- **Per-profile saves** - Mod toggles and edits update only the affected profile when the content hash changes. Toggling or removing a mod updates individual SQLite rows instead of rewriting every mod entry.

#### Logging & privacy (backend)
- **Expanded log redaction** - Tokens, JWTs, paths, IPs, emails, chat commands, and known account names are masked in launcher logs and log encoders. Account list updates refresh redaction needles after load.

### Security & hardening

- **Crash log submission** - NoRisk crash reports send log text from the client. The backend no longer fetches arbitrary URLs; only optional `mclo.gs` links are allowed when inline content is missing.
- **Profile symlinks** - Link paths are validated under the profile instance. Windows directory links use the junction API instead of `cmd.exe`.
- **Content downloads** - Mod and pack installs allow HTTPS downloads only from trusted hosts (Modrinth CDN, CurseForge CDN, GitHub release hosts). File names cannot escape the content folder via `..` or absolute paths.
- **Tauri filesystem scope** - Webview file access is limited to launcher app-data directories (Documents, Downloads, and system temp removed from the default capability). Log windows use a reduced capability without broad file or opener permissions.
- **Custom game directory** - Must be a canonical absolute path that is not a drive root before it is saved or used for path allowlists.
- **Launch hooks** - Pre-launch, wrapper, and post-exit hooks must point at an existing absolute executable. Shell interpreters are blocked. Hooks run with parsed arguments (quoted paths supported), not a shell.
- **Archive extraction** - Forge, NeoForge, and Java installers validate zip/tar entry paths to prevent zip-slip writes outside the target directory.
- **Modrinth filter icons** - Category SVG from the API is sanitized before rendering in the sidebar.

### Bug Fixes

#### Launch & repair
- **Repair fixes the game, not just mods** - Repair verifies and refreshes libraries, client jar, and natives before rebuilding profile mods.
- **Logging config integrity** - Vanilla log4j XML is SHA1-verified on download; a patched `vxl-` sidecar config is used for the JVM (plain-text console layout, lookup-safe pattern).
- **Legacy Java on Apple Silicon** - Custom arm64 Java is rejected when the version requires x86_64 legacy JRE, so launch falls back to the bundled x86_64 runtime instead of failing on missing native libraries.
- **NeoForge Maven downloads** - Installer and metadata use `maven.neoforged.net/releases/...` so NeoForge installs no longer 404 on the installer jar.
- **Forge / NeoForge installer extract** - Nested zip entries (e.g. installer `data/` files) extract after zip-slip checks without requiring parent directories to exist on disk first.
- **Quilt on snapshots** - When Quilt meta omits mappings for a snapshot game version, the launcher adds Fabric intermediary and newer OW2 ASM from Fabric meta for the same Minecraft version.

#### Loader version discovery (profile wizard & settings)
- **NeoForge on Minecraft 26.x snapshots** - NeoForge build ids like `26.3.0.99` map to game version `26.3` (legacy ids such as `21.11.x` still map to `1.21.11`) so NeoForge shows as available when Maven has builds.
- **Forge version matching** - Forge builds match `{minecraftVersion}-...` so `1.21.10` is not treated as compatible with `1.21.1`; matching builds are listed newest first.
- **Quilt and Fabric loader lists** - The UI loads a compact, sorted loader list (stable and newest first) instead of full Quilt/Fabric meta payloads that could truncate over IPC and hide most versions.

#### Profiles
- **Delete removes DB rows** - Deleting a profile removes it from SQLite, not only from the in-memory map.

#### Dependencies
- **Batch dependency resolution** - Required Modrinth/CurseForge dependencies resolve in a batched tree (depth-capped, deduplicated) instead of only fetching the latest single version per dependency.
- **Single save after dependency install** - Installing a tree of required dependencies persists the profile once at the end instead of after each dependency.
- **CurseForge legacy dependency path** - When a CurseForge file declares required dependencies, mod metadata is fetched in batch (`get_mods_by_ids`) and compatible file lists are loaded in parallel instead of one sequential API call per dependency.

#### Local content
- **Rust-side import picker** - Profile local content "Add" opens the native file dialog from the backend (`pick_and_install_local_content_to_profile`) so paths are chosen in Rust. Drag-and-drop still uses path-based install for dropped files.

### Performance Improvements

- **Lighter profile list** - `get_all_profiles_and_last_played` returns profiles without full mod arrays plus a `mod_count`; profile detail refetches full mods when needed.
- **Faster launches** - Library and client downloads skip SHA1 on existing files during normal install/launch (size + ZIP check only). Repair and strict paths opt into hash verification.
- **Hashing off the async runtime** - File SHA1 for local content and downloads runs on blocking threads to keep the Tokio runtime responsive.
- **Local content dedup** - Duplicate paths in local content scans are dropped before hashing and listing.
- **Parallel dependency version lookups** - Required dependencies at the same depth fetch compatible versions concurrently.
- **Linux/macOS Java unpack** - JDK tar extraction runs on a blocking thread with zip-slip checks instead of blocking the async runtime.

### Maintenance

- **Dependency pruning** - Removed unused Rust crates (`machineid-rs`, `byteorder`, `craftping`, `hex`, `zip`, `tracing-subscriber`; `env_logger` moved to dev-dependencies) and unused npm packages (unused React Three, virtualized list, date-fns, immer, lucide-react, and related type packages).
- **Forge / NeoForge deduplication** - Shared loader JVM argument helpers, Maven metadata cache, legacy `-universal` jar suffix rules, and NeoForge processor patching delegates to the Forge patcher (with NeoForge install events).

### Resilience & platform

- **Service status probes** - Mojang-related status is derived from direct HTTP probes (auth, sessions, API) with timeouts instead of relying on a third-party aggregator.
- **WebGL fallback** - When WebGL is unavailable, skin snapshots and the 3D play rig fall back to a flat skin texture instead of a blank canvas.
- **Linux AppImage** - Existing CI step strips conflicting Wayland libraries from the AppImage and re-signs (unchanged workflow, aligned with upstream launcher packaging fixes for NVIDIA + Wayland flicker issues).
